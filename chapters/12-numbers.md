# 第 12 章 数字与证据

客户最常问的是：**loss 对不对得上、性能多少、精度有没有掉。** 这些问题的答案都是数字。
一个没有来源的数字，在周报里出现三次、三次不一样时，整个项目的可信度就没了。

## 12.1 凡是写进 issue、PR、RFC、周报的数字

**必须附来源：可复现的命令 + commit + 配置文件路径（或集群作业的 run-ID）。**

- 和参考值比较时，**写明参考值来源和容差**
- 估算就写「估算」并给出推导；**没有来源的数字不要写**
- **不写「本地测了一下大概是 X」**
- 不确定就去查，查不到就写「未确认」。**不编造数字、run-ID、issue 号、文件路径**

### 好和不好的例子

| 不好 | 好 |
|---|---|
| MFU 大概 41% 左右 | MFU 41.20%（run-ID `perf-r42`，`northpeak/maxtext @ modelx @ 9a1c2e0`，配置 `recipes/modelx-poc/configs/64chip.yml`）；扣掉不训练模块的反向多计后约 40.95%（推导见评论 3） |
| loss 和 GPU 对上了 | 2000 步 loss 均值差 0.0004，噪声带 ±0.002（两次只改执行方式的运行之差），无方向性偏移。参考：GPU 运行 `gpu-ref-r3` |
| 修完快了很多 | 步时 1.82 s → 1.41 s（−22.5%），`step-r10` vs `step-r12`，各取第 100–200 步中位数 |
| 显存应该够 | 估算：参数 + 优化器状态 = 8B × 16 B ÷ 64 芯 = 2 GB/芯；激活未计。**估算** |

## 12.2 数字怎么产生：四条

1. **每个数字都来自一次固定配置的运行**：固定 commit、固定配置文件，不接受「我本地跑出来是这样」
2. **和参考值按写死的容差比**：参考值（比如 GPU 上同一模型的 loss 曲线）和容差都放在仓库里，比对逻辑在代码里，不在某个人的判断里
3. **结果长期存档，按 run-ID 索引**：CI 运行页会过期，长期能找回的只有按 run-ID 存下来的报告
4. **报告、周报、issue 里出现的每个数字都附 run-ID**

run-ID 就是第 10 章 `card.yaml` 里的运行名，也是对象存储里的产物目录。一个 run-ID 应该能回答：用的什么代码、什么配置、什么环境、结果在哪。

## 12.3 「对上了」是什么意思（数值类项目选读）

数值对齐类的问题（TPU 对 GPU、两种并行策略之间），最容易出现的混乱是**「对上了」没有统一口径**：
有的人指逐位相同，有的人指相对误差小于某个数，有的人指 loss 均值在门槛内。门槛常常比噪声还严，比较工具本身没有自证，漏比了张量也报「一致」。

原项目在 `wiki/docs/best-practices/` 放了一份「训练数值差异速查」，后来又写了一篇 RFC 把对齐做成框架。下面几条取自那份速查，复刻时至少定下：

- **门槛按噪声标定，不照搬别处的数**。拿两次「数学相同、只改执行方式」的运行之间的差当尺子：差不超过它、也没有方向固定的偏移，就算对齐
- **先排除不是数值的差异**：dropout、优化器超参数、数据处理约定这几项，一项就能比所有数值来源大一到三个数量级
- **不要求逐位一致**，除非两边真的是同一份计算（同一硬件、同一编译结果）
- **比较工具要有阴性对照**：故意改坏一份数据，确认工具报失败

做数值对齐或改动数值相关代码时，先读一份「精度边界清单」：几乎所有不对齐都出在 16 位与 32 位互转、以及 GPU 上 TF32 的地方，
按清单逐个算子核对两边的乘法、累加、输出精度与舍入位置。这份清单放在 `wiki/docs/best-practices/` 或数值工具仓里，`AGENTS.md` 第 5 节指向它。

## 12.4 两种失败：基础设施挂了，还是数字不对

**CI 失败（或任何验证失败）时，先判断是哪种，在评论里写清：**

| 类型 | 例子 | 怎么处理 |
|---|---|---|
| **基础设施挂了** | 作业没起来、集群异常、超时、配额不够 | 重跑；不是代码的问题 |
| **数字不对** | 超出容差 | 这才是需要查的 |

**不要只说「CI 红了」。** 两种失败共用一个红叉时，红多了，真正的数字问题会被淹掉。
如果你有 CI，让它用不同的状态（或不同的检查名）区分这两种。

PR 里可以用评论命令触发验证（比如 `/loss` 起一次小规模训练对比），**跑完要把结论评论回 PR，不能只回一条「已派发」**。

## 12.5 回归：每个 PR 声明自己会不会改数值

第 7 章的「数值影响」栏和日常回归配合：

- **回归门**：对上一次通过的运行。声明「数学不变」的改动，要求逐位相同
- **对齐门**：对 golden（参考实现的结果），按噪声标定的门槛判

日常回归发现数值变了，对照最近合并的 PR 的声明：声明了会改、且在声明的范围内 → 预期内，更新基线；声明了不变却变了 → 查这个 PR。
